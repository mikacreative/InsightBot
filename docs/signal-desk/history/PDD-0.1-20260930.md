# Signal Desk — Product Design Document

日期：2026-09-29｜版本：0.1｜状态：开发与试点设计；功能完成度以实际验收为准

归属：InsightBot 的独立品牌情报工作流｜首个试点：Sun Life｜开发分支：`codex/signal-desk`

本文是本轮产品设计的权威版本。Obsidian 副本用于业务讨论与检索；修改后应回到本文件统一版本。本文中的设计、目标与验收条件不代表功能已经实现或服务已上线。

## 1. 产品判断与价值

Signal Desk 以品牌目标和目标人群的问题为观察坐标，持续引入外部信息，通过可追溯的证据核验与相对独立的编辑判断，帮助团队识别值得行动、深入研究或继续观察的信号，并修正原有假设。

品牌定向决定“观察什么”，不预先决定“应该得出什么结论”。公共内容中的作者与互动者不能因为主题相关，就被认定为高净值客户或品牌目标人群。产品交付的核心是有边界的判断及决策用途，数据量、热度与生成篇数是辅助信息。

对客户，这是一项可独立说明、报价与验收的增值研究服务。对内部，它是 InsightBot 同仓库中的独立模块，复用已有产品能力；先验证付费意愿、编辑质量和交付成本，再评估是否需要独立产品或独立仓库。开发分支用于本轮实施，后续按正常评审合并，不长期维护一个客户专属 fork。

## 2. 用户、场景与服务边界

| 用户 | 需要解决的问题 | 主要产物 |
| --- | --- | --- |
| 客户策略／品牌负责人 | 外部生活议题是否支持或挑战目前的传播判断 | 精选信号、证据限制、品牌意义、建议处置 |
| Agency 策略与客户团队 | 从零散监测走向可讨论、可进入 Brief 的议题 | 研究清单、议题卡、编辑理由、跨期回看 |
| 内部编辑／研究员 | 控制质量、纠正 AI 推断、管理有限研究预算 | 候选与证据面板、人工审核、采集诊断 |

首期聚焦“品牌研究与传播决策的外部输入”。不承担市场总体测量、个人财富识别、保险产品适合性判断、销售线索筛选或自动投放。没有足够证据可以不出稿，数据采集失败必须与“本期没有新增信号”区分。

## 3. Sun Life 试点与提案衔接

沿用 Sun Life RedNote pitching v7 的主线，把 Signal Desk 放入可选试点／增值服务，说明它如何帮助理解长期安排、代际责任与人生选择。下一代、退休与长寿、家业与代际沟通是初始观察方向，允许发现邻近议题。不得另外发明一套替代客户 Brief 的传播主张。

现有基础服务中的日常监测、常规研究和点点能力应在 SOW 中先划清；增值范围应对应额外的定向采集、补证、独立编辑、审核及跨期学习，避免为既有承诺重复计费。可先附赠有上限的试点，再按品牌数量、观察范围、期数、补证深度、人工编辑时间和数据成本报价。此版不设未经验证的价格或 ROI 承诺。

### 可用于提案的真实研究试跑

2026-09-29，千瓜对“退休生活”和“留学规划”各返回 10 条笔记，日期请求为 2026-08-30 至 2026-09-28。它们是默认接口批次，共 20 个不同 URL，并非全量、随机样本或经确认完整覆盖该时段的总体。JustOneAPI 对其中两条退休笔记补读正文，不增加独立样本数。

- 夏至《退休后再旅游不大现实》自述照护父亲、陪伴母亲出行时的现实限制：[原帖](https://www.xiaohongshu.com/explore/6a9424f10000000028005aa7)。
- 潇湘晨报《60岁阿姨81天环游20国仅花3.7万元》呈现另一种退休经验：[原帖](https://www.xiaohongshu.com/explore/6a963fdd0000000012037ac9)。
- 编辑后的研究问题：家庭讨论退休时，是否充分考虑父母照护、共同出行与家庭分工？处置为“深入研究”，没有形成退休焦虑趋势或金融产品需求结论。
- 留学样本主要涉及申请、通讯卡、offer 和奖学金，暂不足以支持教育资金需求判断，本期不凑稿。

这是实际接口采集后的人工编辑演练，未运行 InsightBot 自动工作流，未验证视频、评论或个人自述事实，也不代表已持续运行或产生营销成效。前轮“二代接班”20 条结果属于另一批次，不并入上述统计。样本作者、全文和供应商原始响应不进入公共代码仓库；内部复现数据留在获授权的本地数据目录。

## 4. 编辑产品设计

### 输入：Brand Brief

每个品牌单独配置业务问题、目标人群假设、议题与排除项、已知判断、观察时间窗、信源、查询词、语言、输出上限、数据与模型预算。人群锚定作为相关性判断条件，页面需清楚标明它是品牌设定，不能变成被观察作者的身份标签。

采集规划包含定向入口和开放入口。前者跟踪约定品牌／人群问题，后者关注可信媒体、研究及邻近议题，并预留独立预算。首轮可以仅开通已验证的社交接口，但要显示开放入口尚未覆盖。

### 编辑流程

1. **采集并记录范围**：记录提供商、查询参数、页码、排序、请求时间窗、实际返回量与失败原因。
2. **统一证据与去重**：按平台内容 ID／规范 URL 合并同源记录，保留多个提供商的独立快照。同一主题的相反观点不是重复内容。
3. **主编初筛**：AI 判断相关性、新信息和挑战现有假设的价值，保留入选／补证／观察／排除理由。代码负责结构、证据 ID 与链接校验，不用固定热度榜替代编辑判断。
4. **补证与不同解释**：按预算读取正文、追查原始出处、寻找反例或替代解释。仅标题不足以形成强结论；未找到反证不等于证明原假设。
5. **策略编辑**：分开写外部观察、证据限制、品牌意义和建议处置。品牌相关性不得改写事实。内容建议只是可能用途之一。
6. **质量校验与人工审核**：无效来源引用、越界推断、无依据数字和覆盖披露缺失应阻止可交付状态。审核人可以批准、退回或否决；批准必须绑定具体版本。
7. **交付与跨期回看**：首版仅预览／导出。后续记录信号进入研究、Brief、行动或被否决的原因，以及后续证实／推翻情况。

### 输出卡片

每条卡片至少包含：标题、外部观察、引用证据、证据深度与局限、可能的其他解释、品牌意义、处置、建议下一步。处置为 `action`（已有充分依据可行动）、`research`（值得补充研究）、`observe`（保留跟踪）、`drop`（排除并保留理由）。栏目数量和篇数都是上限，不补齐空栏目。

客户交付展示精选卡片与本期范围说明；内部工作台保留候选、排除记录、预算和故障诊断。两者读取同一批证据与编辑结果，避免另写一个无法追溯的客户版本。

## 5. 技术架构与 LangGraph 边界

仅为 Signal Desk 引入 LangGraph；现有营销日报的默认 editorial pipeline、任务配置、调度器与频道保持原路径。通过模块与数据契约复用现有候选 ID、编辑骨架及未来的频道渲染能力，避免将品牌情报直接塞入原有“只筛营销新闻”的提示词。

完整产品目标图（0.1 对未接入的自动补证／反证能力明确显示为待人工补充）：`brief → collect → normalize → shortlist → enrich → edit → validate → human_review → approved_output`。预算允许时补证可有限回到检索；校验失败可有限修订；达到上限返回有原因的待研究／失败状态。人审使用 LangGraph interrupt，恢复以稳定的 thread/run ID 定位，不能把重新运行整个任务当作审核恢复。

| 状态层 | 保存内容 | 约束 |
| --- | --- | --- |
| Graph checkpoint | 当前节点、候选引用、编辑版本、审核暂停点 | 本地测试使用持久化存储；进程重启可恢复 |
| 证据与编辑记录 | 原始来源、快照、主张与证据映射、编辑理由、审核记录 | 独立于临时模型上下文，按品牌与运行隔离 |
| 调用／交付记录 | 调用预算、请求结果引用；未来的 delivery outbox | 防止恢复时重复付费调用或重复发送；不能靠 checkpoint 自动保证 |

工具执行器只暴露白名单能力和结构化参数，限制页数、样本数、详情调用数、模型调用数、超时与重试。明确记录预算耗尽和未知调用结果。外部请求失败后的重试必须考虑是否已计费；不得无限自动重试。原始内容是待分析材料，不能作为改变工具权限或泄露配置的指令。

### 证据契约

证据对象至少包含 `evidence_id`、平台内容 ID、规范来源 URL、作者／发布时间的原值与映射、提供商、查询与时间窗、采集时间、指标快照时间、正文深度、商业标签、已核验与缺失字段、原始响应引用。供应商指标不同不可静默合并，字段冲突应保留。

编辑对象保存 `claim → evidence_ids`、推断与局限、不同解释、处置及理由、模型与提示词版本、审核人／时间／版本。模型不生成来源链接，由代码从证据 ID 映射。千瓜规范化字段缺失而 raw 有值时应显式映射，不伪造已核验信息。

### 提供商与配置

AI 提供商经独立适配器接入，首版可选择 OpenAI-compatible endpoint，并显式配置 base URL、model、API key、超时和输出预算。必须实测所选服务的结构化响应与错误行为；“兼容”不能视为功能保证。

数据适配器分别负责千瓜结构化发现、JustOneAPI 正文／其他已验证接口，以及未来 RSS／搜索的外部语境。接口参数和认证方式以实际文档／schema 为准，避免依赖浏览器登录状态推断直接 API 有效。没有密钥时可运行明确标注的离线样例模式；不得用演示内容替代 live 结果。

密钥仅存于环境对应的本地 secret 配置或环境变量，模板无真实值。AI key、JustOneAPI token 与千瓜会话分开授权、配置与健康检查；Mac mini 不自动继承开发机凭证。环境模板应区分必填、可选、运行路径、限额与诊断方法，不将敏感值写入日志、Git 或 Obsidian。

## 6. 隔离、错误与审核

测试数据、checkpoint、日志、端口、进程和环境与旧 InsightBot 分离，不改写原有 runtime 文件或腾讯云生产。品牌 ID 与 run ID 共同约束读写路径，防止路径穿越与跨品牌复用。首版是可信内部人员使用的单实例测试环境，文件路径隔离不等于已具备商用多租户鉴权。

故障状态至少区分：未配置、认证失效、权限不足、限流、网络故障、返回格式变化、部分覆盖、有效零结果。认证问题暂停受影响分支并给出最短恢复路径；不以 UI 操作绕开失效授权，也不把错误解释为没有讨论。

模型不可用或输出不合格时显示失败／待审核，不以硬编码“通用洞察”补齐。人工审核暂停点之前不得调用渠道发送；首版本身不开放外发，批准仅表示该版本可导出。未来接入自动交付需独立设计 outbox、渠道权限和版本绑定。

## 7. 发布范围与路线

| 阶段 | 范围与交付 | 不宣称完成的能力 |
| --- | --- | --- |
| 本轮 0.1：Mac mini 测试 | 独立模块与入口、Brand Brief、LangGraph 状态流、可追溯卡片、审核暂停／恢复、证据导入／离线回放、JustOneAPI live 搜索与 OpenAI-compatible AI 接入、限额诊断、env 指引 | 千瓜自动采集适配、全自动正文补证与反证检索、持续在线商用、全网覆盖、全自动第三方策略师 |
| Sun Life 试点验收 | 配置真实凭证后跑通实际采集与模型编辑，对照人工样刊至少两轮审核，记录成本与耗时 | 未经客户确认的营销成效、数据代表性与财务回报 |
| 后续交付试运行 | 调度、渠道交付 outbox、跨期回看、更多开放信源与研究能力 | 未单独验证的实时预警、多租户商用 SLA |

此表是本轮目标，不是交付实录。如果某个 live 适配器尚未开通或只具备基础搜索，应在运行说明明确列为待配置／未实现，不能把模拟数据的全链路测试写成真实数据验收。

Mac mini 测试目录约定为 `~/Applications/SignalDesk-test`，使用 Python 3.12 独立虚拟环境，服务绑定 `127.0.0.1:18876`，经 SSH 隧道访问。先验证进程／健康页，再验证实际创建任务、审核恢复、导出与重启；仅能打开首页不足以称工作流验收完成。留存实际代码版本、启动方式和运行路径，不复制原生产配置。回退方式是停用独立测试服务，旧系统不依赖它。

## 8. 验收标准

1. 以至少一个品牌 Brief 运行真实图；每个结论引用存在的证据 ID，链接由代码映射；未知 ID 阻止通过。
2. 离线样例模式显著标注，不产生真实数据／模型调用；live 缺少密钥时明确报配置问题。
3. 同一原帖跨提供商不重复计数，同一话题的不同经验保留；只有标题时不升级为群体趋势。
4. 允许零条合格成稿并披露原因；有效零结果、部分失败和认证失败分别验证。
5. 工具与模型调用遵守限额；恢复／重试不会无声重复产生不可控调用。未验证的幂等边界明确列出。
6. 审核前不能成为批准版；暂停状态持久化，进程重启后能恢复；批准绑定具体报告版本，否决有明确终态。
7. 数据路径按品牌／运行隔离；原 InsightBot 的频道、调度和相关回归测试通过；未发生外发。
8. Mac mini 在独立端口完成工作流烟测；真实供应商与模型测试只有在配置凭证并执行后才标为通过。
9. 两轮业务审核记录无依据结论数、实质修改率、审核分钟数、单期 API／模型成本与建议采用／推翻情况。试点后据实际基线再设服务承诺，不以输出数量代替质量。

## 9. 提案与介绍页最小表达

**Sun Life Signal Desk｜持续引入外部观察与独立编辑判断**

围绕品牌目标与目标家庭关心的问题，在约定信源中持续发现线索，通过补证、不同解释与策略编辑，筛选值得关注、深入研究或采取行动的信息，帮助团队发现机会并识别既有判断的盲点。

介绍页建议按四部分呈现：客户得到什么（卡片与讨论议题）；如何形成（发现→补证→独立编辑→人工审核）；一张真实试跑卡（退休与家庭责任，明确个案边界）；试点范围（周期、信源、预算、交付与双方配合）。客户页省去框架名称与技术部署细节，样刊标注“研究试跑”，不包装为已交付的长期产品成果。

## 2026-09-30 团队测试迭代

Mika 已确认推进员工业务配置、人工审稿和受控内网访问。本轮在既有独立分支实现品牌研究表单、配置保存、单页采集计划确认、后台任务与研究历史、卡片修改和版本校验、批准/否决、账号登录与管理员创建账号。表单中的目标受众仍是假设，不是采集对象已验证的身份。关键词、主题与排除项由员工检查，不宣称已自动完成研究规划。

Live 计划每轮上限1次搜索、20条样本、1次AI编辑；执行前明确确认，重复执行同一计划返回已有任务。进程中断后标记待排查，不自动重试潜在付费调用。Replay 采用原始样刊的品牌与时间范围，不按新设置重新采集。后台完成与人工审稿并发时保留已批准/否决终态。

内网采用单个共享工作区：admin管理账号，editor可研究、修改与审核；不是客户级权限隔离。数据接口密钥继续在服务器配置。服务采用用户登录后启动的LaunchAgent，私有地址HTTPS18878与本机18876双入口，未公开互联网。操作与验收见[团队测试说明](TEAM-TEST.md)。定期调度、自动反证检索、正文扩展、货币预算结算和客户独立空间仍未实现。
