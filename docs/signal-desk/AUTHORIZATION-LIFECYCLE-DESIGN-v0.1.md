# 付费研究授权生命周期方案 v0.1

日期：2026-10-13（方案）／2026-10-14（裁定与实现）｜状态：四项推荐方案已由 Mika 确认；本机实现与隔离验证，未部署。

范围：批准时校验、跨月续期、额度下调／撤销及旧计划兼容。延续已修复的本地账本 POSIX 锁，不引入数据库迁移，不修改 env、CI/CD 或生产。每日请求次数轴、外部通知、账户全入口费控和全自动发布另行实施。

## 1. 已裁定的四项

Mika 于 2026-10-14 确认四项全部按推荐方案实施。下表替代项仅保留作取舍记录，不是当前待决。

| 项 | 推荐 | 替代与取舍 |
| --- | --- | --- |
| A：跨月续期 | 默认到月末停止付费；启用定时时可显式选“按原上限续期”，并填写有效截止日期。没有明确续期条款就暂停待确认。 | 所有定时任务自动续期至撤销：操作更少，但会形成持续支出授权；或所有跨月都手动批准：最简单，自动化连续性较弱。 |
| B：撤销边界 | 以账本的预留获准为分界。撤销成功后不能再创建新预留；此前已获准调用允许完成／结算，不自动重试。 | 严格阻止尚未真正发出的请求：还需统一请求派发器，协调撤销与网络发送。单靠调用前再查一次，无法消除最后检查到网络发送之间的窗口。 |
| C：批准是否占额度 | 批准只签授权，按实际付费调用逐次预留；批准时检查本轮已核算的最大付费需求是否能容纳。批准不保证稍后仍有余额，执行前及每笔调用仍要检查。 | 批准即锁定整轮金额：能承诺余额，但未执行计划长期占用，需新增到期释放、分批结算及重复确认幂等机制；定时未来轮次不能无限提前占钱。 |
| D：谁能批准 | 品牌 admin 管理额度／续期许可／品牌级撤销；已有 researcher 可在授权范围内确认计划、启用定时和撤销自己的任务授权。reviewer 不因此获得花费权限。 | 付费计划全部由 admin 批准：控制更集中，但每轮或新方案需要额外审批。保留现有全局 admin 对品牌的管理权限。 |

建议组合：A 推荐项 + B 以预留为界 + C 逐次预留 + D 额度内 researcher 确认。默认不开通自动续期；研究者只在管理员明确设置的规则内确认，不新增 reviewer 的付费权限。

## 2. 实现前基线（2026-10-13，保留问题来由）

- `research_v2.create_plan()` 已写 `contract.envelope`，实际是生成方案时的环境快照。
- `WorkspaceV2.confirm()` 检查 checksum／最新计划／ready 后改变状态，未重新校验预算、当前账号状态或生成批准快照。
- `save_schedule()` 做当前账号和品牌权限核对；触发使用 `plan_snapshot`，`scheduling_v2.frozen_run()` 只滚动查询日期，旧信封 period 一并继承。
- `enrich()` 优先读快照；没有 contract 的旧计划读当前 env。更改 env 上限不能撤销已有快照。
- P0 已让本地同账本授权／结算串行化，尚没有独立的可撤销授权记录或每月续期规则。
- `_plan_hash()` 排除 contract／preflight；工作区的完整性 checksum 包含它们。采集缓存身份与花费许可不能继续混成一个概念。

## 3. 推荐模型：批准记录不变，当前许可可撤销

需要区分三种对象；这些结构现由 `authorization.py` 实现；本节描述的额外边界以下方实现说明为准。

1. **品牌额度规则**：品牌、规则版本、当前状态、每自然月上限、谁可确认、允许的续期范围、稳定账本标识。币种为 CNY，时区固定 Asia/Shanghai；不同任务／模式共享品牌同月额度。
2. **任务授权 grant**：授权 id、品牌／任务、研究内容哈希、批准者／批准时间、规则版本、模式／来源／调用额度／交付规格、付费金额边界、期限与续期条款。冻结“这次同意什么”，不因余额变化改写。一次研究与可重复定时授权明确区分。
3. **本轮许可及账本预留**：关联 grant、run、实际自然月及规则版本；检查当前授权状态和剩余额度。保留来源／调用 id，供结算、异常恢复与审计使用。

批准记录是历史依据，不是永久通行证。每次付费预留同时检查冻结许可与当前限制，取更严格的约束；提高品牌上限不自动扩大旧 grant，降低上限／撤销立即限制新预留。不得通过换 plan id、mode 或月份多发一份独立的品牌预算。

**持久化实现**：额度规则变更、grant 发放／撤销、月度续期许可与 reserve／settle 的关键事件，使用同一本地账本及同一 P0 锁串行处理。新事件类型须有版本、操作者、时间、关联 id；现有 reserve／settle 金额意义不变。工作区保存授权引用与审计展示，不另存一份可独立放行的当前权限真值。事件带 `schema_version=authorization-1`，账本头保存唯一 ledger_id。只追加事件，不自动迁移或重写已有运行状态。

**账本身份**：批准绑定 ledger id；路径属于部署配置。路径不匹配／账本缺失时拒绝付费，不能自动新建空账本恢复余额。初始化新账本需显式管理操作。ledger id 要和实际载体核验，不能只信计划里的字符串；改账本的正式迁移另行设计。

## 4. 批准时校验与双阶段确认

### 4.1 生成计划只给预览

规划不发放付费授权。体检读取当前规则、账本余量和冻结调用需求，展示品牌月上限、本轮付费需求、有效期／续期方式。正文与评论按真实付费来源核算，千瓜次数单列；未计入模型、固定席位及人工费用必须标清，不能沿用模式配方冒充完整成本。

### 4.2 点击确认时重新校验

- 从当前账号文件重新确认启用状态，再核品牌角色；不只信登录时的 session。
- 校验最新计划、内容哈希、来源／调用额度／交付标准与用户看过的确认预览一致。
- 在同一账本锁内核当前规则版本、授权状态、期界、余量、账本身份与已核算的付费需求。策略或权限变化则要求刷新确认；不静默换成更高额度或更长有效期。
- 付费需求不能容纳时拒绝发放付费 grant，并说明“调低范围／补充额度／明确选择不付费”。免费观察不是自动降级为同等交付。
- 写入带幂等确认 id 的 grant；重复确认返回同一授权，不重复占用／创建。
- grant 先落账本，工作区再保存引用。若第二步中断，恢复只查同一确认 id 并核对内容，不重新发放或调用供应商。账本记录不匹配就停止；孤立 grant 没有已绑定且确认的工作区 run 不能花费。

默认推荐 C 不在确认时占款。因此余额竞争依旧可能导致本轮之后无法开始，但每笔都不会超出当前上限。需要保证整轮资金时，必须选择 C 的另一方案并追加预留生命周期实现。

### 4.3 执行时持续检查

启动／出队时核 grant、账号、计划内容、实际月份和当前规则；在正文／评论的每一笔预留前，再核可撤销状态和金额。在同一 P0 临界区完成“当前规则／撤销状态→余额→预留”，禁止先查撤销、解锁、再单独授权。供应商网络调用在锁外；此边界与 B 的推荐一致。

身份和品牌角色来自现有账号／品牌源；账本中的授权撤销是金额操作的串行判据。若要求删除账号／品牌角色与所有进程付费门禁具有同样的即时原子性，权限修改操作也须先写撤销事件；不能只靠每笔读账号文件宣称完全无竞态。

## 5. 跨月续期

- 以新付费预留当下的 Asia/Shanghai 自然月归账，不从旧 plan.period、计划研究窗口或错过的 scheduled_for 推算。
- 无自动续期许可：月末 grant 到期，新月运行暂停，待新确认；不以免费片段悄悄维持原交付承诺。
- 有显式续期许可：仅在下一次实际触发时，核有效截止日、创建者账号／品牌权限、grant 状态、当前规则和研究内容未变化，再幂等生成当月许可。多个任务同月读取同一个品牌额度池；未用完额度不结转。
- 新月有效上限不高于原已批准上限与当前品牌规则上限；增加额度必须重新确认。查询窗口可按既有规则滚动，研究方法／来源／调用额度改变则暂停重批。
- 一轮跨越月末：旧月已获准预留按旧月结算，不把历史收费搬到新月；下一笔需新月许可。没有续期许可则停止进一步付费并记录未完成范围；不要临时把一次研究改成跨月重复任务。
- 重启不补跑错过的日程，保持现有调度规则。续期只换许可期界，不能制造一次额外研究。

## 6. 下调、撤销与恢复

| 操作 | 推荐行为 |
| --- | --- |
| 降低品牌月上限 | 写新规则版本；历史已付及未决预留不变。低于已占用时剩余额度视为 0，所有新预留拒绝，不伪造退款。 |
| 撤销单个 grant | 串行写 revoke 事件；后续该 grant 不得预留，相关任务暂停；其他已授权任务不受该撤销影响。 |
| 停用品牌付费 | 撤销／停用品牌额度规则；该品牌全部新付费预留拒绝。不是停止整个 InsightBot。 |
| 撤销与调用并发 | 以同一账本锁排序：先获准的预留允许完成结算，撤销先落账则拒绝。未决结果保留占用，禁止自动再发。 |
| 后续恢复或加额度 | 不删除撤销记录、不复活旧 grant。需新的显式确认；调度默认保持暂停，重新启用时再绑定新授权。 |

免费本地整理、已取得材料的审阅和历史结果读取可以继续；暂停阻止的是后续受撤销范围控制的外部付费操作。既有预留的结算不要求 grant 仍有效，否则撤销会造成账本永远无法收尾。

## 7. 旧计划与缓存

- 旧计划、快照及结果保留可读；无新 grant 的计划不再因为后来 env 配好就获得付费权。
- 手动重确认可以创建新 grant；旧自动日程默认暂停待确认，不批量补发授权、不迁移旧数据库。
- 研究内容哈希用于采集缓存复用；grant／当月许可／账本身份另行绑定执行审计。改变授权不自动重抓已取得证据；命中缓存不计费，但不得借缓存恢复未经许可的新付费调用。
- 缓存复用仍须通过品牌隔离与准确输入校验；grant 是执行许可，不能成为跨品牌缓存复用凭证。

## 8. 实施顺序与验收

1. 冻结 §1 规则和 grant／事件字段，补带时钟的纯校验函数；不先改部署 env。
2. 将规则／撤销判定纳入 P0 的预留临界区，再接批准预览与幂等确认。确认与工作区落盘中断需可核对恢复。
3. 接实际触发的月度许可与跨月行为，随后接撤销、恢复和旧计划重新确认；同步 UI 的期限、费用口径与暂停原因。

必须覆盖的场景：

- 生成后更改额度／停用账号／移除品牌权限，再确认时拒绝；预览版本变化不暗中确认。
- 多线程／多进程批准与调用同一品牌，月额度仍共享；确认不重复授予额外预算。
- 上海时间月末／月初、UTC 换日与月未换的边界；旧预留旧月结算、新请求新月核验。
- 无续期暂停；有续期只创建一份当月许可；截止期、方法变化、撤销、重启不会续开。
- 撤销与新预留两种排序；已获准但未完成调用结算；失败／超时不重发、不自动释放未知支出。
- 降低上限到已占用以下、加额度不复活旧 grant、换账本不重置余额。
- ledger id 缺失／不匹配、旧计划无 grant、批准记录已写但工作区保存中断，均不隐式花费。

## 9. 当前实现与验证边界（2026-10-14）

- `authorization.py`：管理员规则、批准预览、幂等 grant、有效期限与月度许可、撤销及在同一 P0 锁内检查／预留；授权绑定品牌、冻结研究内容、账本身份、路径及准确运行。独立进程使用同一份本地账本。
- `WorkspaceV2`：确认时重查当前账号／品牌角色、最新计划及预览版本；实际触发与出队再校验，过期／撤销暂停。定时授权与单次授权分别发放，手动批准不顺带授权日程。恢复 grant 需新确认，已撤销日程仍需重新启用。
- `research_v2.enrich`：正文和评论每次新调用都核当前 grant／规则，旧 contract/env 或显式 envelope 不再放行付费。已获准请求可以在撤销后结算；未决请求继续占额度，不重发。
- 月度许可事件在新月**首次实际付费预留**时幂等追加，不提前发放或占款；调度触发先核本月资格。已授权的查询窗口可以滚动，来源／模式／调用额度改变需重批。
- 默认账本落点为当前私有 workspace root 下的 `spend.jsonl`；显式配置 `SIGNAL_DESK_SPEND_LEDGER` 时使用它。管理员必须显式设置规则，首次初始化会创建 ledger_id；后续旧 grant 不接受换路径／删账本重建。没有搬迁旧环境账本或数据库，旧计划需重新确认。
- 计划中的旧 `contract`／`preflight` 保留为历史／规划预览，不再决定付费许可。授权 UI 单独展示准确的正文＋评论最大需求及当前余量；不将旧模式配方、H 或环境额度误呈现为有效授权。通用 pre-flight 硬拒、每日次数轴与通知仍是独立 P1，本轮未实施。
- 旧输入／grant 缺失仅允许明确的不付费确认；旧自动日程没有新执行授权时暂停。正常交付仍需要人工审阅，本轮不改变发布边界。

测试入口：`tests/signal_desk/test_authorization_lifecycle.py`；既有付费补读测试改为在隔离账本通过真实批准流程取得 grant，仍保留旧计划不能被环境变量意外激活的反向断言。测试不接真实供应商、不使用真实客户或凭证。

仍需说明的边界：账号／品牌成员修改沿用现有源文件，门禁在每次预留前读当前权限；若要求权限文件变更与撤销具有同一个跨进程线性化时点，还需将权限修改入口一并接入撤销事务，本轮未扩展账号管理。金额撤销／下调与新预留已经同锁串行。所有保证限于同一本地账本的合作调用，不覆盖旧服务版本、直接供应商调用或跨主机并发。
